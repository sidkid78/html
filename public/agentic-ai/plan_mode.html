Architecture Analysis

The Anatomy of Plan Mode:
The Read-Only Fortress

No one knows Claude Code better than Claude Code itself. When you trigger Plan Mode, you're entering a special operating environment where the agent is restricted from making any file edits, running terminal commands, creating or deleting files, or making commits. It is a pure research and analysis phase.

By asking Claude to reflect on its own system prompt, we see its internal directive: "I research and analyze, create a plan, present the plan for approval, and wait for confirmation."

SAFE STATE

This is crucial because it allows you to ask "stupid," zero-judgment questions. You can validate your assumptions and build up the state space—the complete map of all possible configurations and logical paths—of your problem. Because the agent is in a read-only state, there is zero risk of a hallucinated git reset --hard or mangled CSS. As the model itself confirms, the purpose is to load your context window with vital information before you switch out and start the actual mutation.

The Two Workflows: Plan-to-Code vs. Spec-First

01. Plan then Write

There are two primary ways to leverage this mode. Use the session to brainstorm, then immediately execute once the logic is sound.

GOLD STANDARD

02. Spec-First

For mid-to-large sized features, this involves having Claude Code research the codebase and then write a persistent markdown file—a "Spec"—that defines the architectural requirements.

Why do this? Because agents are ephemeral. They are stateless and their context windows eventually get blown away. By writing the plan to a file like specs/feature_v4.md, you create a version-controlled document that survives the session. You can review it, tweak it, and commit it. This allows you to hand off massive chunks of work to your agent in single swings, pushing the limits of what these models can actually accomplish.

Meta-Prompting:
Writing Prompts that Write Prompts

This is where we get into high-leverage engineering. Using Plan Mode, we can engage in meta-prompting: the process of writing a prompt that instructs Claude to generate a new, highly optimized prompt (the Spec).

In our demonstration, we updated an Infinite Agentic Loop—a recursive setup where Claude generates and tests versions of a solution until it reaches a desired outcome or a specific failure point. We used Plan Mode to architect V4 of our spec, moving from single HTML files to a modular directory structure containing isolated CSS, JS, and HTML files.

By asking Claude to "showcase what the output directory looks like after running three agents," we validated the logic before any code was written. This conversation primes the agent, ensuring it understands the structural requirements before moving from the abstract plan to the concrete execution phase.

Executing the Infinite Loop with Parallel Agents

Once the plan is solid, we transition from theory to heavy lifting. We exit Plan Mode and enter what I like to call "Auto-Accept YOLO Mode."

Using a high-performance model like Claude 3.5 Sonnet, we can trigger the "think hard" keyword—a specific instruction that activates the model's deeper reasoning capabilities. In our workflow, we used a custom /infinite command to read our newly created V4 spec and fire off 10 parallel agents.

These agents work in batches (Wave 1 and Wave 2), each handling a unique UI theme. Because we did the heavy lifting in Plan Mode, we can watch five parallel agents work together to accomplish their tasks with zero conflicts. Each agent uses about 40k tokens and multiple tool calls, but because the architectural plan was clear, they deliver perfect results in minutes.
